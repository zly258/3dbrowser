> 目标：任何内存优化都不得破坏「加载 / 模型结构 / 单选 / 高亮 / 框选 / 属性 / 浏览 / 删除 / 多模型」。
> 执行方式：本地 `npm run dev` + 浏览器（Playwright 或手工），窗口 1600×900。
> 结果记入 `docs/memory-optimization-plan.md` §9，并附截图到 `preview-tmp/`（不提交）。

## 0. 环境准备

1. `npm run dev`，记下实际端口（5173 被占用时是 5174）。
2. 浏览器开发者工具打开 Console，勾选 Preserve log。
3. **清空站点 localStorage**（保证默认值确定）：
   ```js
   localStorage.clear(); location.reload();
   ```
4. 测试文件：
   - 全模型：`C:\Users\14532\Downloads\批量导出_20261113_093819.nbim`（2.9 GB / 1271 块）
   - 子集：`D:\models\hf-test\nbim-200chunks.nbim`（437 MB / 200 块）
   - LMB：`D:\models\hf\1#炉给水管道.lmb`、`2#炉汽水管道.lmb`、`AAZ02201-FCS54.2-1.lmb`
5. 记录基线：`performance.memory`、状态栏文本、控制台错误数。

> 说明：同一浏览器上下文重复加载会残留堆内存，**每组大模型测试前请新开无痕/隔离上下文页**，并在测量前执行一次 GC（DevTools Memory → Collect garbage）。

## 结果记录 · 2026-11-14 框选 OBB→AABB 包球预筛

提交：`a6e5333`（独立提交，不压缩）

### 实现

- `selectInteractablesByScreenRect` 增加逐实例预筛：用 OBB→AABB 精确公式
  （世界半尺寸 = |矩阵列| × 局部半尺寸）构造"世界 AABB 包球"，6 平面测试剔除必不命中的实例，
  疑似命中再走原盒测试。判定集与盒测试完全一致。

### 调试过程中证伪的三个方案（均有实测证据）

1. 顶点级球（getBoundingSphereAt）× 列范数缩放：圆形板类构件顶点球半径 0.749 < 其 AABB 角点距离 1.06，误剔 1 例
2. 局部盒球 × 列范数：列范数在"旋转×非均匀缩放"实例矩阵下偏小（球 2.19 < 世界盒对角线半径 2.26），误剔 3 例
3. 根因：盒测试判定的是【世界 AABB】（旋转后盒化放大 √2），任何"局部球 × 矩阵"都不包住它；
   必须用 OBB→AABB 公式从局部盒+世界矩阵直接导出世界 AABB 的精确包球
